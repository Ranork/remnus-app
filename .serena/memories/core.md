## DB Tables
- `workspaces` — workspace list; `icon` (emoji/lucide/https URL), `icon_color`, `billing_owner_id` (nullable FK→user; the paying user whose plan governs this workspace's limits; migration 0027)
- `workspace_items` — sidebar items (pages + databases), recursive nesting via `parent_id`
- `standalone_pages` — markdown content for page-type items
- `databases` — schema (JSON) + views (JSON) config
- `pages` — database rows; `properties` JSON column. Recurrence link columns (migration 0043, dedicated columns NOT `properties` keys — same call as `card_collapsed`): `series_id`, `occurrence_date` (RECURRENCE-ID), `series_detached`; UNIQUE (series_id, occurrence_date) makes materialization top-up idempotent
- `recurrence_series` — one repeating calendar rule + the template its occurrences are stamped from (migration 0043, script `src/db/apply-0043-recurrence.ts`). `rule` = JSON `RecurrenceRule` (RFC 5545 subset, not an RRULE string) from `src/lib/recurrence/rule.ts`; `template` = title/properties/icon/content/dateShape; `parent_series_id` set by a THISANDFUTURE split; `materialized_until` = horizon reached. **Occurrences are REAL `pages` rows, never a virtual expansion** — in Remnus every row is also a page with body/sub-items/links/MCP addressability, so a computed ghost could not be written into. Two invariants: (1) the past is immutable — a rule change SPLITS the series (`splitSeriesAt` ends the old one the day before and inserts a new row) instead of mutating it; (2) a "dirty" occurrence (body/title/properties diverged from template, nested sub-page, any page_link, `agent_edited_at` set, dragged off its `occurrence_date`) is detached and kept in place, never regenerated away, and its date is EXDATE'd on the new series so no empty duplicate stacks on top. Top-up is **read-triggered** (`loadRecurrenceState(databaseId, windowEnd)` from `CalendarView`) so the feature needs no cron and works on self-hosted Docker. Services in `src/lib/services/recurrence.ts`, actions in `src/lib/actions/recurrence.ts`, engine tests `npm run test:recurrence`. Full semantics: `AGENTS.md` → **Recurring Calendar Cards**, design rationale `.ai/RECURRENCE_DESIGN.md`
- `user`, `account`, `session`, `verificationToken` — Auth.js tables. `user.analytics_consent` (nullable 'granted'|'denied'|null, migration 0029, script src/db/apply-0029-user-consent.ts) = effective server-side analytics-capture permission, persisted by ConsentProvider for cookie-less server contexts (MCP/OAuth). First-touch acquisition cols `signup_ref`/`signup_utm_source`/`_medium`/`_campaign`/`signup_referrer` (nullable, migration 0031, script apply-0031-signup-attribution.ts) copied off remnus_first_touch cookie at signup → pinned as $set_once PostHog person props (signup-funnel channel breakdown). NOT read by the admin landing-traffic card (that pulls all-visitor referrers straight from PostHog via getTrafficSources). getTrafficSources also now returns a `campaigns` array — a `?ref=<tag>`/`utm_source` breakdown read via HogQL extractURLParameter($current_url), covering ALL landing visitors (not just signups) since AttributionCapture's cookie only ever reached PostHog at signup time before this
- `workspace_members` — user↔workspace join with role
- `agent_tokens` — MCP bearer tokens scoped to workspace; columns: id, workspace_id (CASCADE), name, agent_name, token_prefix (8-char, indexed), token_hash (bcrypt cost 12), scope ('read'|'write'), created_by, created_at, expires_at (nullable, null = no expiry), last_used_at, revoked_at

## Claude Desktop .mcpb bundle
- `mcpb/` — one-click Claude Desktop install. .mcpb packages a LOCAL stdio server, but Remnus MCP is REMOTE HTTP → bundle ships a thin launcher (mcpb/server/index.js) running bundled `mcp-remote` against ${user_config.server_url} (default https://www.remnus.com/api/mcp — MUST be the www canonical host; apex 307-redirects to www and mcp-remote rejects a resource-indicator mismatch). mcp-remote bridges stdio⇆Streamable-HTTP + runs OAuth 2.1/PKCE browser flow on first 401 (DCR vs /api/oauth/*; localhost redirect allowed). No token to paste. Distribution (follow-up): no UI download link yet + attach to GitHub release. Install test is manual (Claude Desktop GUI).
- GOTCHA — Windows multi-instance sign-in race (fixed in bundle 1.0.1, do not regress): recent Claude Desktop builds start the server 2-3x simultaneously (desktop chat + Cowork/Code shared pool + "era probe"). While no token is on disk each instance 401s and tries to bind mcp-remote's OAuth callback port — `3335 + md5(serverUrl)[0..4] % 45816` (16819 for prod www), pinned to the registered redirect_uri's port once a client exists, so NO free-port fallback. mcp-remote's own lockfile guard is explicitly skipped on win32 (`process.platform === 'win32' ? null : await checkLockfile(...)`), so losers die of unhandled EADDRINUSE → "Unable to connect to extension server" forever. mcpb/server/index.js now elects a leader via an atomic `wx` lock at `<MCP_REMOTE_CONFIG_DIR|~/.mcp-auth>/remnus-launch-<md5(url)>.lock`; followers poll for `<hash>_tokens.json` across every `mcp-remote-*` dir, then start without touching the port. Stale locks reclaimed via pid-liveness + age. The follower poll timer must NOT be unref'd (nothing else holds the event loop before the proxy starts → exit 0 → host reads it as a crash). Token present ⇒ path skipped entirely. Launcher log: `~/.remnus-mcpb.log`; host log: `%APPDATA%/Claude/logs/mcp-server-Remnus.log`.
