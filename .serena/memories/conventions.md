## Auth
- NEVER call `auth()` directly in server actions/components — use `getCurrentUser()` from `src/lib/auth/session.ts` (React.cache wrapped)
- Workspace-locked project-window sessions (`npx remnus open`) are DENY BY DEFAULT: `auth()` returns null for them, `getCurrentUser()` throws. Only workspace-content code opts in via `getCurrentUserAllowingWorkspaceLock()` / `getSessionAllowingWorkspaceLock()` and must then call `assertWorkspaceLockAllows(user, resolvedWorkspaceId)` before any admin shortcut. Raw `authWithWorkspaceLock` is for `session.ts` only. The UI follows the same line: the `(app)` layout derives ONE `isProjectWindow` boolean from the lock claim and passes it to `WorkspaceSidebar` / `MobileNavWrapper` / `ActivityTracker` — never re-derived client-side. Everything that isn't workspace content is omitted in JSX (not CSS-hidden), so account-level server calls like `getUserAgentTokenCount` / `getMyTier` — both of which call `getCurrentUser()` and therefore throw here — never fire. See AGENTS.md → Project Install §4.
- All workspace actions → `assertWorkspaceAccess(workspaceId)`
- All database/page actions → `assertDatabaseAccess(databaseId)`
- Unauthenticated → `redirect('/login')`; unauthorized → throws
- **Security headers (R10, 2026-10-02):** baseline headers for ALL routes live in `next.config.ts` → `headers()` — `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'`. Don't drop them. frame-ancestors/XFO only apply to a FRAMED page (Tauri loads top-level → unaffected; YouTube embeds have Remnus as parent → unaffected); relax per-path only if a surface must be cross-origin iframe-embeddable. Full CSP (`script-src`…) and HSTS deliberately NOT added (need dev testing + domain verification) — see gitignored `.ai/status-reports/SECURITY_AUDIT_2026-10-02.md` + prompts R10.5. Known low-sev items tracked there/prompts R10.1–R10.5: MCP existence oracle, rate limiting, CLI server-name→AGENTS.md sanitization, `remnus://auth` session-fixation, Android `allowBackup`.

## Data Patterns
- JSON column pattern for dynamic properties (no EAV, no extra tables)
- `SelectOption`: `{ value: string; color?: SelectOptionColor; icon?: string }` (icon = emoji/`lucide:Name`/upload URL, same format as `PageIcon`; rendered via `PropertyTags.tsx`'s `OptionIcon`) — `normalizeOption` for backward compat with plain strings
- Date formatting: `formatDateValue()` from `properties.ts`; never hardcode `'en-US'`
- Bulk paste import (`BulkRowsDialog` → `bulkCreatePages`/`bulkUpdatePagesByMatch`): headers match column NAMES case-insensitively; unknown headers are dropped; unknown select/status values are auto-appended to the schema as new options. `content` is a RESERVED header (`CONTENT_HEADER`/`extractRowContent` in `propertyCoercion.ts`, added 2026-08-04) that writes the row's markdown BODY, not a property — unless the database has a real column named "Content", which wins. Omitted `content` leaves an existing body untouched (partial patch, same as the properties merge). `syncPageLinks` runs per row AFTER the transaction, never inside it. Use JSON not TSV/CSV for multi-line bodies; `MAX_BULK_ROWS` 500 and Next's default 1MB server-action body limit both apply

## Dashboards (added 2026-09-22)
- `workspace_items.type` is now `page | database | dashboard`. There is no DB CHECK, so the compiler is the only thing that finds the call sites — widen the TS union and let `npx tsc --noEmit` enumerate them. The full audit lives in `AGENTS.md` → **Dashboards**; don't redo it from scratch.
- The dashboard spec (`src/lib/dashboard/schema.ts`) is the single zod source of truth for renderer AND MCP writes. Never write a second schema for it. Blocks are addressed **by `id`, never by array index**, and carry a data SOURCE, never rows.
- Row filtering/sorting for BOTH database views and dashboard blocks lives in `src/lib/tableFilters.ts` (pure, no 'use client'). `DatabaseView.tsx` imports it — do not inline a copy back into a component.
- A dashboard route is server-rendered end to end: resolve block data in `src/lib/dashboard/data.ts`, never per-block client fetches.
- Every dashboard write (MCP tools AND web actions) goes through `src/lib/services/dashboards.ts` (`createDashboardInWorkspace` / `patchDashboard`). Don't add a second write path: it owns per-block validation of touched blocks only, reference normalization, compare-and-swap, and the `warnings` self-check. Keep block shapes OUT of MCP `inputSchema` (`z.array(z.any())`) — the catalog is the `remnus://dashboard/catalog` resource, generated from zod so it cannot drift.
- Service error text (`DashboardInputError`) is English and agent-facing; the web editor logs it and shows its own localized message.
- (V2 R8.3) Chart colours = `--chart-1…8` + `--chart-muted` tokens (globals.css, light steps under catppuccin), validated with the dataviz `validate_palette.js` — re-run it before touching them. `ChartPoint.colorIndex` keeps an option's slot (colour follows the entity). Never put an HTML `<title>` element in a server component (React 19 hoists it to <head>); use the `title` attribute. Side panels: `ui/sheet.tsx`.

- Bulk graph mutations happen with sigma detached (`renderer.setGraph(empty)` → mutate → `setGraph(graph)`); attached, sigma indexes every add/merge event one by one (1,500 rows: ~1.3 s). Start force passes/animations only after re-attaching.
- The public accessibility widget must stay out of the app: a new top-level `(app)` route goes into `APP_ROUTE_PREFIXES` (`src/lib/accessibilityWidget.ts`); `AccessibilityWidgetOff` in the `(app)` layout is the safety net, not a replacement (it cannot stop a pre-hydration flash).

A code node's tree parent is a `folder` edge: never let the page-tree (`hierarchy`) loop claim a code node (priority 0 beats 6 and silently turns folder edges into page-tree edges — the first version did). Code nodes carry no trust/agent state and stay out of mentions and "Needs attention". Nodes placed outside the radial tree (tags, files, folders) need the deterministic golden-angle nudge, or siblings with one neighbour coincide and FA2 cannot separate them.

## MCP / Agent Token Conventions
- Token format: `<MCP_TOKEN_PREFIX>_<prefix8>_<secret>` (env var `MCP_TOKEN_PREFIX=rmns`)
- Verification: look up by `tokenPrefix`, then `bcrypt.compare(secret, tokenHash)` — never iterate all tokens
- **Agent access follows membership (2026-09-25):** `findPatForAuth` / `findOAuthTokenForAuth` (`src/lib/services/agentAccess.ts`) read the token together with its holder's `workspace_members` + `user` rows in one query; `effectiveAgentScope` → non-member (non-admin) = 401, `viewer` = `read`. Any new path that removes a member or makes them a viewer calls `revokeAgentAccess` / `restrictAgentAccessToRead`; account deletion calls `revokeAllAgentAccessOf` BEFORE nulling `created_by` (a still-live creator-less PAT predates that, keeps its scope, and shows as "Deleted account" in the panel). The OAuth consent screen shows/clamps a viewer to `read`. Owners see and can revoke members' OAuth connections in the AI Agents panel. Test: `npm run test:agent-access`.
- **Open pages adopt server changes (2026-09-25):** `BlockEditor` (body, `markSaved` after a save), `PageEditor` (row properties/title), `StandalonePageEditor`/`DatabaseView`/`DashboardHeader` (title/name) adopt a refreshed server value only when there is no unsaved local edit and not within 2.5s of one; title effects re-run after every refresh because the layout's default "Remnus" `<title>` comes back. Don't "simplify" these back to read-once initial state.
- `/api/mcp` is whitelisted in `auth.config.ts` (`isMcpRoute`) so middleware never redirects MCP requests
- `export const runtime = 'nodejs'` required on MCP route (bcryptjs not Edge-compatible)
- Write tools must check `ctx.scope !== 'write'` and return an error — never execute the mutation
- Audit logs in `agent_activity` are best-effort (`.catch(() => {})` — tool response must not depend on audit success)
- **`/api/mcp` is stateless-only (as of 2026-08-03) — do not re-add a stateful SSE branch.** It used to also support a legacy stateful SSE transport (hand-rolled `SseCustomTransport` + `activeSseConnections` Map, for older Cursor/Windsurf/Continue/Antigravity configs: GET with `Accept: text/event-stream` opened a `ReadableStream` and handed back an `event: endpoint` handshake with a `sessionId`, later POSTs to `/api/mcp?sessionId=...` fed it). ## Live refresh (rebuilt 2026-09-21) — see AGENTS.md → "Live refresh (the change signal)"
- There is NO server push. `src/lib/realtime/publish.ts` was a no-op (an in-memory EventEmitter
  can't fan out across Vercel's multi-instance runtime); it and its 45 call sites were deleted.
  Don't reintroduce a `publish()` that does nothing — the next reader will think it's live.
- `computeChangeVersion` MUST include the `deleted_items` tombstone aggregate. Without it a
  delete LOWERS `max(updatedAt)` instead of raising it, so removals never refreshed anything.
  Tombstones are insert-only, which is also what keeps the version monotonic.
- It's ONE statement, membership included (V2 R9: `changeSignalForUser` / `heartbeatSignalsForUser`, `with ws(id)` CTE + version + `n`), not N awaited queries: at a 2.5s poll the Turso
  round-trips are the cost. Each max is an index seek (migration 0055 `(…, updated_at)` indexes; Turso rows read per poll 7,100 → 1,866).
- (V2 R9.8) Body/schema/row edits reach the signal through `workspaces.content_updated_at`, kept by SQLite triggers (`content_clock_*`, migration 0056) on every write path — app code never writes it, and a new content write path needs nothing. A migration that rebuilds `standalone_pages`/`databases`/`pages`/`workspaces` drops these triggers (like `search_*`): rerun `apply-0056-content-clock.ts`; `db:drift` checks them. 1,866 → 39 rows per poll.
- `GET /api/activity/changes` is the fast, read-only half; `POST /api/activity/ping` writes a
  `user_sessions` row on every call and must never run at the fast cadence. Keep the changes
  response ~20 bytes — the whole mechanism exists because a 10s `router.refresh()` poll
  (~100 KB RSC payload per tick) was the dominant Vercel Fast Origin Transfer cost.
- Cadence invariant: an IDLE normal tab still costs exactly one request per 30s. Fast polling
  is only for a project window (flat 2.5s while visible), a normal tab while the heartbeat
  says `agent: true` (agent_activity in the caller's workspaces within 3 min, R5), or within
  ~90s of an observed change (1.6× backoff, then it stands down entirely). A window `focus`
  checks once (throttled 2s).
- (R5, 2026-09-30) The version is in whole SECONDS: a second write in the same second does not
  advance it. The `(app)` layout passes `renderedAt` (server ms, taken before its reads);
  `mayPredateRender` → one extra "settle" refresh on a later tick. Only the desktop sidebar
  (the one given `renderedAt`) drives `router.refresh()` — the hidden mobile-drawer copy made
  every refresh fetch twice.
- (R5) `workspaces.updated_at` is the 7th branch. A write that changes what a sidebar/open page
  shows but touches none of the versioned columns (reorder, reparent, membership, access
  request, comment delete …) must call `touchWorkspaces(...ids)` — not bump items' updatedAt.
- (R5 follow-up) The change signal carries `n` (visible workspace count → a removal/add counts as a change) and
  `h: 1` while `v`'s second is open (`signalExtras`); `TabHost` settles via `changeIsHot()`, `GraphScreen` via its
  payload's `generatedAt`. Keep all consumers settling — whole-second versions lose same-second writes otherwise.
- MCP body edits: `update_page` `tick` / `append` (`services/bodyEdits.ts`) — never resend a body just to tick a task.
  `move_item` `position` renumbers siblings. Curated Lucide names reach agents only via `{{LUCIDE_ICONS}}` in docs and the
  dashboard catalog (not tool schemas).
- (R8.8) Agent presence adds NO request and nothing to the change poll/heartbeat bodies: the sidebar presence is read by the `(app)` layout (`loadAgentPresence`), the page provenance with the page read. `ActivityTracker` only re-broadcasts the heartbeat's existing `agent: true` (`AGENT_EVENT`/`agentIsActive()`). Presence reads `agent_activity` = audit data → `PRESENCE_READ_WINDOW_MS = min(60 min, shortest plan auditDays)` keeps it inside every workspace's `auditVisibleSince`; keep that `min`. Aggregate in SQL (newest per connection / per target), never ship the hour's raw rows. Provenance is content (knowledge stamp, version history, review hash), no audit window. Never guess which agent is working: one listed connection may be assumed, several → unnamed row.

  keystroke <15s). Never gate on `mousemove`: the 10s idle timer it replaced meant a human

## Context-pack MCP rules
- Prefer the composing `prepare_context` tool over overlapping list/get tools. Context Pack v2 uses BM25 + native OKF-aligned metadata + link graph; `get_page`, `query_database`, and `get_related_pages` remain drill-down surfaces.
- Smart default is 2,000 tokens and only for meaningful multi-page product/coding work; skip greetings, formatting-only work, and a single known item or context usage increases.
- `related` refs (P13): neighbours of the top 3 concepts, voted by the seeds' scores, ≤ 6, their JSON size (≤ 8 % of the budget) reserved BEFORE bodies are sized — appending them after the bodies left 0.9 refs per default pack. Graph signals change the refs, never the body ranking (PageRank there let an index page take a body slot in half the tasks). Re-check with `bench:context` (docs/ report asserts refs beat the same number of lexical refs).
- Every MCP call returns an actor-bound 30-minute `contextRunId`. Manual/Smart keep it advisory; Strict requires it for actual Remnus mutations. It does not replace write scope, auth, destructive confirmation, or client-specific local-code hooks.
- `human-reviewed` means an authenticated Remnus user reviewed the exact current title+body hash. Imported `human:*` is `external-human-asserted`; agents may set draft metadata/machine provenance but never review themselves.
- `maxTokens` constrains compact JSON (1k-16k); label truncation, return `estimatedTokens`, `selectionReason`, and warnings, and treat retrieved content as untrusted reference data.
- **Finding (P10, 2026-09-23):** match with `foldText()` (`services/textFold.ts`: NFKD, strip marks, locale-free lowercase, `ı`→`i`) on BOTH sides — never `toLocaleLowerCase('tr-TR')` (it made "Invites"/"API" unmatchable by lowercase tasks). Retrieval stays lexical: the agent passes `keywords` (synonyms + the workspace's language, ≤24×60, weight 0.5, measured) and the same one-line rule is in `renderInstructions`, the CLI AGENTS block, the skill and `context-first.md` (token budget +~56 tok/session). Corpus = one `db.batch`; the inverted index is cached per process (~24 MB LRU) under `getKnowledgeCorpusVersion` (change version + counts + knowledge maxima; null in the hot second = not cached); `stale` is recomputed per call. Knowledge tables stay OUT of `computeChangeVersion` (measured +50% per UI poll). `search_workspace` (2026-09-24): ranked FTS5 (migration 0052, contentless `search_fts` + `search_docs`, 11 `search_*` triggers are the ONLY writers) with the LIKE-skeleton + GLOB scan as fallback (< 3 letters, CJK/Thai, index missing, zero hits). Details: AGENTS.md → Performance Rules → "Context & search read path" and Migration Notes 0052.
- **No embeddings (P11, 2026-09-24, Hakan):** retrieval stays lexical — no workspace content goes to an embedding provider; don't add a vector path without a new decision. ## Joining a connected project (`npx remnus join`)
- **A workspace id is not a credential.** It lives in a committed `.remnus/config.json`, so
  everyone with a clone has it. Re-read membership from the database on every render AND
  again inside every action; the URL/form value is always client input.
- **A non-member must learn nothing** about a workspace — not its name, not its members, not
  whether it exists. `createAccessRequest` returns the same `pending` for an id matching no
  workspace (nothing is stored), and a non-`connected` install-poll payload carries the
  *project* name, never the workspace's. Anything else turns this into an enumeration oracle.
- **Do not widen `mintAgentToken`.** It is owner-only and the AI Agents panel mints there.
  `join` uses `mintProjectAgentToken`, a separate export sharing the private `issueAgentToken`
  (row + funnel capture + first-agent email). Loosening a shared gate is how an escalation ships.
- **Clamp scope by role, and refuse rather than downgrade.** A `viewer` asking for write gets
  `Errors.viewerCannotWrite`, so the CLI can explain it instead of writing a credential that
  fails on first use.
- **Each join revokes this person's previous token for this project** (workspace + `created_by`
  + the `Remnus CLI · <project>` name), *before* `checkCanAddAgent` — otherwise a re-join is
  blocked by the slot it is about to free. `countAgents` counts every un-revoked PAT and every
  join mints one. Tell the human; never drop a session silently. **Open question: the quota is
  per token, not per person** — one human on three machines still costs three agent slots.
- **A request costs nothing; an approval costs a seat.** `checkCanAddSeat` runs at approval
  time, inserts as `member` (never the requested scope, never owner), and a refusal leaves the
  request PENDING so the owner can free a seat and approve the same row.
- **`join` writes exactly one file**: `.remnus/credentials.json`. Never `config.json` (its
  `calibrated` flag above all), the `AGENTS.md` section or `.claude/settings.json`. It fills a
  *missing* `.mcp.json` entry or `.gitignore` block but never overwrites one. `git status`
  after a join must be clean — that is the assertion worth keeping a test for.
- **`init` on an already-connected project joins it.** Reconnecting needs `--reconnect`:
  silently re-pointing a committed config forks a team's shared memory, and nobody notices
  until both halves have content.
- Recovery advice must name `join`, not `init`, wherever the project is connected and only the
  credential is missing (`mcp.js` 401/403 + missing-token, `doctor`'s no-token branch).
